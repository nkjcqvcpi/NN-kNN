# Repository expectations

This branch is `LLM` (`llm/`): the shared NN-kNN core plus LLM retrieval and host integration (T3). Use `tools/t3_*.py`, `model/t3/`, and `tests/test_t3_*.py`. Other stages belong to their own branches; standalone NN-kNN material belongs to main.

- The shared NN-kNN core (files listed in `tools/check_nnknn_core.py`) is owned by main. Do not edit it here; change it on main and sync it (`docs/NNKNN_CORE.md`). `tests/test_nnknn_core.py` fails if it drifts.
- Results and logs are not in git. Recording is mandatory (owner, 2026-11-22): `tools/t3_need_matching.py`, the one T3 entry point that trains, requires `--study S` (argparse error without it) and records one run unit per seed in the shared `NN-KNN/runs/`, `runs/t3/S/s<seed>/` (TensorBoard event files: curves, training events, seed summary, and the metric weights as the named state `metric`); it writes no per-seed file. A complete unit is detected before any training and never trained again. Its generated `protocol.json` and `summary.json`, rebuilt from the units, go to `results/t3/s1_single_hop_retrieval/need_matching/<study>/` unless `--output` says otherwise. Anything that needs the trained metric reads it from its unit (`model/t3/metric_provenance.py`; legacy `s<seed>/metric.pt` files are no longer read): the two host pilots take the unit directory as `--metric-checkpoint`. The host pilots and need collection (`t3_public_host_pilot`, `t3_internal_host_pilot`, `t3_public_set_utility`, `t3_prompt_pilot`, `t3_train_need_queries`, `t3_host_smoke`, `t3_public_data_audit`, `t3_prepare_host`) train nothing and still write the output folders they always wrote; they require an explicit `--output`/`--out`; point it at `results/t3/<stage>/` (see `results/README.md` there), never at `reports/` or `docs/`. Reports written by agents or people go in `reports/` (tracked); generated outputs never do.
- Use `model/regression_workflow.py` for regression and set `task_type="regression"`.
- Environment and dependencies are managed by uv only. The single `pyproject.toml`, `uv.lock` and `.python-version` (Python 3.14) live on `main`; one venv at `NN-KNN/.venv` is shared by all worktrees (`NN-KNN/{main,rl,llm,neural-cbr}`). Set the user environment variable `UV_PROJECT_ENVIRONMENT` to its absolute path once per device. In `main` run `uv sync` and `uv run python ...`; in another worktree run `uv run --project ../main --no-sync python ...`. torch is the Intel Arc XPU build (Windows x86_64 only; `environments` in the toml). No pip, no `requirements*.txt`, no hand-made venv. wandb was removed; training data is recorded with TensorBoard through `model/common/tracking.py` (see `docs/NNKNN_CORE.md`, "Run tracking").
- This project has no README, CHANGELOG or LICENSE by owner decision (2026-11-21); obsolete tracked content is deleted, not archived (Git history keeps it).
- Use synthetic datasets for quick validation; run `uv run python codex/smoke_test.py --mode imports` and the branch tests (`uv run python -m pytest`). Avoid full benchmarks for routine checks.
- `checkpoints/`, `*.pth`, and `*.pt` are local artifacts.
- `datasets/` in the repo holds loader code only (`datasets/*.py`). Data files and preprocessed caches are not tracked: they live in the shared `NN-KNN/datasets/` next to the worktrees (or `$NNKNN_DATASETS`), found through `datasets.paths.datasets_root()`, which raises if the directory is missing; datasets that a library downloads (scikit-learn's California Housing, OpenML) stay in that library's default location instead (`~/scikit_learn_data` or `$SCIKIT_LEARN_DATA`; the `openml` cache), and torchvision images, which have no library default, stay in the shared directory. Never add data files to git (`.gitignore` blocks everything under `datasets/` except `*.py`). No model weights are kept in the repo.
- Historical provenance hashes and commit IDs in experiment evidence describe the original experiment, not the reorganized source.
