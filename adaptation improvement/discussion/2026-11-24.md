# Initial adaptation discussion

Date: November 24, 2026.

## Motivation and owner proposal

Retrieval can already give a prediction close to the target. Applying a large adaptation can then make it worse. The owner proposes a head alongside NN-kNN retrieval that outputs an adaptation weight: confident retrieval should generally need less adaptation, while less confident retrieval may benefit from more.

## Current implementation checked

The neural-CBR source inspected at commit `411abd4bdb960fd7e81b595a55c59ffff1305e43` predicts a regression residual internally, then returns the adapted prediction:

```text
delta_y = adapter(query-to-neighborhood difference, y_retrieved)
y_adapted = y_retrieved + delta_y
```

A gate can either scale the residual or interpolate the two predictions; these are algebraically equivalent:

```text
y_final = y_retrieved + alpha * delta_y
        = (1 - alpha) * y_retrieved + alpha * y_adapted
```

Classification's primary adapter predicts residual class scores. Its logit-residual alternative uses a different normalization. Scores, probabilities and class IDs must remain distinct when defining a classification gate.

## Initial suggestions and subsequent status

- Use a learned gate with output between zero and one. Highway Networks and mixture-of-experts models provide established precedents; retrieval-based machine translation provides a related confidence-weighted interpolation example.
- Treat retrieval confidence as evidence for the gate. Low retrieval confidence does not establish that the adapter is reliable. An adaptation weight is not automatically a calibrated confidence estimate.
- Candidate gate inputs include neighbor distances, label disagreement, retrieval-weight concentration and the retrieved prediction. A separate variant could also inspect the proposed correction.
- Earlier suggestion, superseded as the main training design: freeze the existing retriever and adapter and train only the gate. This remains a possible diagnostic ablation, not the intended training procedure. The owner's subsequent decision is to train the gate with the adapter; see below. Final test data remain untouched and retrieval self-exclusion is preserved.
- Compare retrieval-only, full adaptation, a globally tuned adaptation weight and a learned per-query weight. Measure harmful corrections as well as average predictive error.
- When training the gate and adapter together, monitor the applied correction `alpha * delta_y`: a larger residual can compensate for a smaller gate. Whether an explicit correction-size penalty is needed remains open; see the later loss-simplification discussion.

These suggestions have not been experimentally tested. The later training decision below governs the main design; detailed architecture, loss terms and experiment settings remain undecided. The current adapter can already learn a zero residual; the gate's proposed benefit is an explicit, inspectable decision about how much correction to apply.

See [References](../docs/REFERENCES.md) for the implementation, historical report and papers.

## Follow-up on a unified gate for classification and regression

### Owner preferences

- Use neighborhood evidence, following the motivation of Adaptive kNN-MT.
- Use one gate mechanism for classification and regression. Overlap between the gate's information and the classification adapter's existing inputs is acceptable; avoiding redundant information is not a design requirement.
- Prefer both nearest-case distance and weighted mean case distance, unless a useful alternative summary can preserve both meanings.

### Proposed common statistics

Let `w_i` be the nonnegative normalized retrieval activations for the current query, not the learned case biases. Let `d_i` be the actual query-to-case distances. A proposed fixed-size gate input is:

```text
[d_min, d_mean, weight_concentration, label_disagreement]

d_min = min_i d_i
d_mean = sum_i w_i * d_i
weight_concentration = sum_i w_i**2
mu = sum_i w_i * t_i
label_disagreement = sum_i w_i * ||t_i - mu||**2
```

Minimum and weighted mean distance answer different questions; keep both as a two-number summary. For an all-case baseline, use the eligible training cases, excluding the training query itself. Masked variants must explicitly define whether the minimum is over all eligible candidates or only retained contributors.

Weight concentration needs only squaring and summing weights already computed by retrieval. Its reciprocal is the effective number of weighted cases: ten equally weighted cases give concentration 0.1 and effective count 10; one case carrying all weight gives both values 1. Choose one representation rather than including both. This is not a count of independent observations or a guarantee of correctness.

The same label-disagreement formula applies to both tasks:

- Regression: `t_i` is the numerical target, preferably in training-standardized units. The statistic is weighted target variance.
- Classification: `t_i` is a one-hot class label and `mu = p_r`. The statistic simplifies to `1 - sum_c p_r[c]**2`, the Gini impurity. For class probabilities `[1, 0]`, `[0.9, 0.1]`, and `[0.5, 0.5]`, it equals 0, 0.18, and 0.5 respectively.

Thus `p_r` is the complete classification distribution, while label disagreement is a scalar summary of its spread. For regression, the mean prediction alone cannot determine this spread.

### Status and interpretation

The four-statistic input and a small sigmoid-output network are proposals, not a finalized implementation. The same architecture and input definitions can be used for both tasks, with parameters trained per dataset. Sharing one trained gate across datasets is a separate question because feature scales and task distributions differ. Any fitted input scaling must use training data only.

These statistics describe neighborhood support and disagreement, not calibrated confidence. The gate should learn how they relate to useful correction rather than enforce a rule that disagreement always requires more adaptation. No model code has been changed and no experiment has been run.

## Training decision: the gate trains with the adapter

The owner specifies that `G` should train together with the adaptation module because its useful output depends on the current retrieval and adapter behavior. Training retrieval at the same time is not required. This replaces the earlier suggestion of gate-only training as the main procedure.

Treat the adapter and gate as one adaptation component for parameter updates, freezing, checkpoint selection and restoration:

| Schedule or phase | Retrieval parameters | Adapter parameters | Gate parameters |
| --- | --- | --- | --- |
| Sequential: retrieval training | Update | Frozen or not yet initialized | Frozen or not yet initialized |
| Sequential: adaptation training | Frozen | Update | Update |
| Alternating: retrieval block | Update | Frozen | Frozen |
| Alternating: adaptation block | Frozen | Update | Update |
| Joint: adapter warm-up, if configured | Frozen | Update | Update |
| Joint: joint-training block | Update | Update | Update |

`G` is a small trainable network mapping the proposed retrieval statistics to a scalar, followed by a sigmoid to produce `alpha`. A four-input MLP with one hidden layer was discussed as an example, not a finalized architecture.

Both adapter and gate receive learning signals from the task loss on the final gated output `y_retrieved + alpha * delta_y` (or the corresponding classification score/probability path). The gate follows the adapter parameter group under separated or summed joint objectives; precise auxiliary residual losses, correction penalties and their coefficients still need an explicit definition before implementation.

Retrieve current neighborhoods and recompute gate statistics as retrieval changes. During a retrieval block, freezing adapter/gate parameters must not accidentally disable the gradient through their computations into retrieval when the existing schedule includes post-adaptation loss. Detaching gate inputs would be an additional experimental choice, not a consequence of freezing its parameters.

Inspect the applied correction, not `alpha` alone. An explicit correction-size penalty is optional and remains under discussion. Joint optimization can trade a smaller gate against a larger residual. Avoid initializing the sigmoid so close to zero that it suppresses learning of the adapter. Initialization, regularization strengths and optimizer settings remain open.

Gate-only training with a frozen adapter can be retained as an optional diagnostic comparison. It is not a prerequisite for the agreed main design. This decision records the intended training behavior only; it makes no implementation changes and reports no new experiments.

## Proposed controls for gate and residual scale compensation

Status: suggestions in response to the owner's concern, not an adopted objective or implemented change.

Penalizing only the applied correction `alpha * delta_y` does not resolve the decomposition ambiguity: a smaller gate and proportionally larger residual leave both prediction and applied-correction penalty unchanged. Such a penalty can still serve the separate objective of keeping the final prediction near retrieval.

### First proposal: retain supervision of the ungated residual

Keep an auxiliary loss that trains the adapter's raw proposal against the required correction:

```text
required_residual = target_representation - retrieval_prediction
L_residual = mean(||raw_delta - required_residual||**2)
L_final = task_loss(retrieval_prediction + alpha * raw_delta, target)
```

Use numerical targets for regression and one-hot targets with the primary residual-score classification mode. This formula is not a target definition for the logit-residual ablation.

The current `model/t1/sync.py` already contains an `L_delta` term. In ungated regression it duplicates final MSE. With a gate, keeping this term on the raw residual makes it distinct from gated final loss. Classification's primary mode already fits `r_hat` to `one_hot(y) - p0`. Do not silently redefine that term on `alpha * raw_delta`, which would lose the proposed anchoring effect.

An illustrative proposed objective is `L_final + beta * L_residual + lambda * applied_correction_penalty`, alongside the declared retrieval objective and schedule. Coefficients and the exact penalty remain undecided. Both gate and adapter can still update on every adaptation step. The auxiliary term gives the adapter a learning signal even when the gate is small. In joint retrieval training, the gradient routing through retrieval and the residual target must be declared explicitly.

Example: retrieval 100, true target 102. A raw residual 2 with gate 1 and a raw residual 20 with gate 0.1 both predict 102. Their raw-residual squared errors are 0 and 324, respectively. Separate supervision therefore makes inflation costly. It is a soft control, not a proof that the gate is calibrated or uniquely identifiable.

### Optional hard limit on the proposed residual

For a fixed, nonlearned bound `B`, parameterize `raw_delta = B * tanh(adapter_output)`. Then each applied output-coordinate change satisfies `abs(alpha * raw_delta_j) <= alpha * B`. This prevents arbitrarily large raw proposals but does not remove all scale ambiguity within the bound.

The current primary classifier already uses `tanh`, giving a per-class-score bound of 1. The regression aggregate output is unbounded; a regression bound would need a declared scale, preferably training-standardized target units, and validation-based selection without test access. A bound may exclude useful large corrections. This is an optional comparison, not a settled default or a proposal to bound arbitrary logit residuals without further analysis.

### Other options and limitations

- Penalizing raw residual magnitude alone favors smaller raw residuals and larger gates for a fixed final change; it is not a way to make the gate a calibrated confidence estimate.
- If compensation persists, a stronger experimental alternative is separate gradient routing on the same adaptation steps: train the adapter on its ungated residual/prediction objective, and train the gate on final gated loss with the adapter proposal detached for that loss. Both modules still train together in time. This changes the agreed final-loss routing and would require an explicit design decision.
- Monitor raw residual size, applied correction size, gate values, ungated adapter error and final error together. No gated model has yet been trained, so compensation remains a potential issue rather than an observed failure in this project.

## Discussion of simplifying the losses

Status: the owner proposes alternatives and asks for assessment; no new loss choice has been finalized.

The owner suggests replacing raw-residual supervision with a penalty for departure from full adaptation, `beta * (1 - alpha)**2`, and potentially omitting the applied-correction penalty because retrieval and final prediction losses already reward accurate predictions.

### A prior toward full adaptation

The proposed alpha penalty is a valid soft preference for full adaptation. It distinguishes otherwise identical decompositions: `alpha=1, delta=2` and `alpha=0.1, delta=20` apply the same correction, but the latter pays an additional gate penalty. For a fixed applied correction, if the adapter can represent that correction directly, taking alpha toward 1 minimizes this penalty. It can therefore encourage an almost always-open gate. This is a tendency, not a theorem about the actual finite network: the gate has neighborhood inputs the adapter does not, and the adapter may not be able to absorb its query-dependent output.

The penalty also charges genuinely helpful suppression. With a fixed overlarge or harmful adapter proposal, the gated prediction loss may favor a small alpha, while the alpha penalty pulls it upward. Its strength is a modeling choice, not simply a cheaper equivalent of raw-residual supervision.

Raw-residual supervision instead asks the adapter to predict the required ungated correction. It does not require alpha to vary or guarantee that the gate will help: if the adapter predicts the true residual perfectly, alpha=1 is also an appropriate solution. Its arithmetic is only an additional subtraction and squared-error reduction; it does not require another adapter forward pass and is already represented by the existing L_delta term.

### Is an applied-correction penalty necessary?

For fixed retrieval in regression, squared final error already penalizes overshooting the target. Moreover, with applied correction `c = y_final - y_retrieved`, the triangle inequality gives `||c|| <= ||y_final - y|| + ||y_retrieved - y||`. If both predictions are accurate on a query, their difference is necessarily small. An explicit magnitude penalty is therefore not mathematically required for regression prediction accuracy and may suppress necessary corrections.

Classification requires a distinction between class-score magnitude and predictive loss: cross-entropy can reward increased true-class margin after the predicted class is already correct. It does not directly enforce small score corrections. For either task, training loss does not guarantee behavior on unseen examples; an explicit size preference is an additional regularizer or explanation constraint, to be evaluated as such.

### Compensation can also be useful

The gate receives neighborhood statistics unavailable to the adapter. Two queries can therefore have identical adapter inputs but different gate inputs. If their required residuals are 1 and 10, a shared adapter proposal of 10 with respective gates 0.1 and 1 fits both. This is a useful division of work, not automatically pathological inflation. Raw-residual supervision also penalizes this solution, because the shared proposal differs from one query's full residual.

Distinguish unbounded proposal growth without predictive benefit from a useful multiplicative decomposition. Neither auxiliary residual supervision nor alpha-to-one regularization is universally superior. A small gate is an adaptation fraction, not a direct measurement of confidence or absolute correction size.

### Current assessment

Keep joint adapter/gate training as agreed. Retrieval and gated-final prediction losses are the core objectives. For an accuracy-focused experiment, compare a condition without added gate/size penalties against weak alpha-to-one regularization and the existing raw-residual supervision as separate alternatives, rather than stacking all penalties. Any omission of existing auxiliary losses must be explicit in a new experiment configuration; historical baselines are unchanged. Treat a correction-size penalty as a separate accuracy/regularization/explanation tradeoff. Use matched comparisons to determine which choices help held-out predictions and harmful-correction rates. A mostly open gate is acceptable if it is the validation-supported outcome, rather than something to prevent artificially. These alternatives remain proposals and no training has been run.

## Latest proposal: separate correction magnitude and direction

The owner proposes two adaptation heads, potentially using a shared model: one predicts the correction's scale using the four neighborhood statistics; the other predicts direction using the current NN-CDH approach. The purpose is to predict scale and direction directly without interpreting either as confidence or reliability. Both heads remain part of the adaptation stage and follow its training schedule.

### Mathematical meaning

A strict decomposition is `correction = m * u`, with `m >= 0` and `||u||_2 = 1` whenever a direction is used. Then `m` is the norm of the actual correction. A vector proposal `v` can supply `u = v / ||v||_2` when nonzero; zero-vector behavior must be explicitly defined. Simply multiplying two unconstrained heads would retain the earlier scale ambiguity. A smooth direction vector with a variable norm would also retain part of it.

This `m` differs from the old interpolation fraction `alpha`: it has units of correction magnitude, need not be restricted to [0, 1], and is not a confidence probability. Regression can use training-standardized target units. Classification needs a declared score or probability space; the current primary implementation adapts class scores.

### Inputs and possible sharing

One candidate is a shared trunk over the current NN-CDH inputs (query-minus-neighborhood representation, retrieval prediction/class mass, and optional nominal differences). Its direction head produces `v`; its magnitude head receives the shared context plus `[d_min, d_mean, C_w, D_y]`. The four statistics remain central, but giving the magnitude head adaptation context avoids assuming that they alone determine the required correction size. This routing is a suggestion, not a finalized architecture.

### Averaging conflicting correction targets

The owner's intuition holds for the predictable mean under squared-error regression: with a fixed retriever and adequate representation/capacity, the optimal correction is the conditional mean of `target - retrieval_prediction` given the information the model uses. Opposing residuals +10 and -10 with equal probability at indistinguishable inputs average to zero. Consistent +10 residuals average to +10.

Uncertainty alone does not imply a small correction: equally likely residuals 0 and +20 average to +10. Small corrections can also occur because retrieval is already accurate. The scale should therefore be called predicted correction magnitude, not an uncertainty estimate. Classification cross-entropy does not in general average raw score residuals in the same way.

Do not train magnitude directly toward each observed absolute residual if the desired behavior is cancellation. `E[|residual|]` differs from `|E[residual]|`: the +10/-10 example gives 10 for the former and 0 for the latter. Final prediction loss should govern the composed correction; any additional magnitude target needs separate justification.

### Direction training requires care

For scalar regression, unit direction is +1 or -1. Computing `sign(v)` gives zero gradient almost everywhere, so final prediction loss alone cannot train that raw direction head through the sign operation. Using `tanh(v)` is differentiable but its variable magnitude would undo strict separation. A zero-sum direction for binary class-score corrections has a similar two-direction issue.

One practical candidate consistent with the current NN-CDH training is to retain a raw proposal `v` trained with the existing residual-fitting loss, while only its normalized direction enters the final correction. The final task loss trains magnitude; the existing residual objective supplies direction-head learning even for scalar outputs. Both heads still update in the same adaptation steps. This option, its loss weights, gradient routing through retrieval, and zero-vector handling remain to be chosen. An ordinary unweighted positive/negative sign classifier is not automatically equivalent: majority residual sign can differ from the sign of the mean residual.

For classification score vectors, a common score offset does not affect softmax probabilities or argmax. Whether to center directions before normalization is another explicit design choice; it must not be silently assumed equivalent to the historical adapter.

### Evidence and status

Weight Normalization (Salimans and Kingma, 2016) provides an established magnitude/direction reparameterization of network weights, not proof for this output-level adapter. The proposed two-head NN-kNN architecture has not been implemented or tested. The previous gate alternatives remain documented for comparison.
