# T1 neural CBR pre-registration, 2026-10-13

Status: frozen before any tuning or confirmation run of this phase. Items marked
**PI** are proposed defaults that the PI may replace before step D (tuning)
starts; a replacement is recorded as a dated addendum below, never after any
evaluation-seed result exists. Machine-readable copy: `configs/t1/prereg_20261013.json`.

Why: earlier T1 results are exploratory. Seeds 30–34 have informed decisions (EMA
conclusion, schedule recommendation, `v_small` choice), so they cannot confirm
anything tuned now. This phase tunes on validation streams of development seeds
only, then confirms once on fresh seeds. Claims are worded from the endpoints
below whatever the outcome.

## Endpoints

Error is 1 − accuracy (classification) or train-standardized RMSE (regression).
Per task, the effect is the log error ratio log((e_F + ε) / (e_ref + ε)), with
ε = 0.5 / n_test for classification and 0 for regression, averaged over the
seed-paired runs. Tasks are pooled by random-effects meta-analysis (REML,
Hartung–Knapp). GMR = exp(pooled log ratio).

| ID | Comparison | Test | Supported if |
|---|---|---|---|
| E1 | F vs NN-kNN retrieval-only on the same core (reuse gate) | one-sided superiority | Holm-significant and GMR ≤ 0.97 |
| E2 | F vs alternating default at F's budget and stopping rule (synchronization gate) | one-sided superiority | Holm-significant, GMR ≤ 0.97, and all guards hold |
| E3a | F vs CatBoost (frozen HPO winner) | non-inferiority, margin δ | one-sided 95% upper bound of GMR < 1 + δ |
| E3b | F vs TabM (frozen HPO winner) | non-inferiority, margin δ | same |

- **δ = 0.10 (PI).** Sensitivity at 0.05 and 0.20 is descriptive only.
- Holm correction over {E1, E2, E3a, E3b} at family-wise 0.05; Benjamini–Hochberg
  at q = 0.10 for secondary analyses.
- Primary analysis: the 20-task legacy group plus the 10-task transfer group
  (30 tasks). Each group is also reported alone. No superiority claim if the
  transfer group's interval excludes 0 in the opposite direction.

**Guards (gate 5, C3, C11).** F's pre-adaptation GMR vs retrieval-only ≤ 1.02;
fixed-metric locality ratio vs the default ≤ 1.10; median correction size ≤ 1.25 ×
the default's.

**Secondary.** Validation-temperature-calibrated ECE (median) ≤ pre-adaptation
ECE + 0.02; wrong-to-correct flips ≥ 2 × correct-to-wrong (classification); log
loss and macro-F1 for churn and MIC; six-method ranks over distinct methods
(CatBoost, TabM, MLP, kNN, NN-kNN retrieval-only, F); cost (training and
inference time, active cases).

**Fallback wording.** E1 fails: "no detectable gain from reuse on tuned cores".
E2 fails: "no detectable schedule effect" (or "gate 5 fails" if a guard fails).
E3 fails: "trails tuned CatBoost/TabM by X% [95% CI]".

## Tuning (step D)

Development seeds only, validation streams only, in this greedy order; each
block starts from the incumbent and replaces it only by its acceptance rule.
The starting incumbent F0 is the batch-64 validation selection (joint, summed
objective, adapter warm-up 5, retrieval scale 1.0, `w_post` 0.25, `w_near` 0.1,
`v_small` 0, adapter rate 0.003).

1. **H6 selection rule and seed count**: leave-one-development-seed-out
   comparison of selection rules; adopt a rule or seed count only if it beats the
   current one by more than 1 LOSO standard error. Dev-seed test streams are used
   here as the declared inner held-out stream, never for early stopping, and are
   spent afterwards.
2. **H1 retrieval guard and `w_pre`**: feasible only if, on every task, mean
   validation pre-adaptation error ≤ 1.02 × retrieval-only + 1/n_val.
3. **H2 classification output** (score scale κ ∈ {1, 3, 10}, `logit_residual`) ×
   `v_small` {0, 0.1}, with a validation-fitted temperature. Primary output mode:
   `nominal_residual_scores` (PI); the two modes are reported separately.
4. **H5 budget and stopping rule**; references get F's budget in confirmation.
5. **H3 adapter capacity and regularization**: replace only if the 80% LOSO
   interval excludes 0 and the gain is ≥ 1%.
6. **H4 neighbourhood size** (optional), only if H6 shows selection can separate
   candidates, and retrieval-only then gets the same extended grid.

Every candidate's validation table is published, including failures.

## Retention (step G), proposed thresholds (PI)

The existing pilot values in `configs/t1/_base.yaml` (activation threshold 0.05,
smoothing 1.0, minimum retrieval count 2, minimum activation mass 0.1, regression
success tolerance 0.5, allowed loss increase 0.05). Primary policy:
`provenance_only` (PI) vs `random` and vs `bias_current` at K = 0.5, Holm within
the family.

## Forbidden

Dropping tasks after results; moving δ or thresholds after any evaluation-seed
result; rerunning evaluation seeds (except bitwise-identical reruns after a
crash, logged); promoting a runner-up; tuning on transfer tasks; pooling CPU and
XPU arms within a comparison; citing the full study's batch-32 tuned-core plan
results for a confirmatory claim.
