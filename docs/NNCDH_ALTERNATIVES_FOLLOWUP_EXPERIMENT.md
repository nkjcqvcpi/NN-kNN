# More alternatives to NN-CDH: declared experiment

November 27, 2026. Study `ar2`, experiment `alt_v1`. Declared before fitting these candidates. Local CPU only; the same 14 datasets and seeds 40–42 as `ar1`. Reuse its 42 recorded contexts, including frozen representations, train-only scaling, exact neighbors, base activations and train/validation/test targets. No retrieval or old candidate is retrained.

**Training scheme: sequential, frozen retrieval for every new family.** Neural vote attention changes adapter voting weights only; the core's base activations remain fixed. Tree and transport fitting receives saved arrays and has no gradient path into retrieval. These results contain no joint/alternating experiment for the new alternatives. The [cross-study scheme explanation](../reports/NNCDH_ALTERNATIVES_REPORT_2026-11-27.md#training-scheme-sequential-with-retrieval-frozen) clarifies how a future forest-to-retrieval feedback loop would differ.

## Three new designs and two controls

1. **Neural vote attention.** Learn a shared query-case scoring MLP on `[q, case, q-case, y_case-p_retrieved]`, hidden widths 64/32, ReLU, dropout 0 or 0.1. Add `4*tanh(score)` to the log of each positive base activation, then softmax within the existing neighborhood. Aggregate the actual case targets with these new weights. Zero base weights remain zero. The last layer starts at zero. This can reweight cases but cannot invent a missing class or leave the neighborhood's regression target range. Train on leave-one-out retrieval contexts using final NLL/MSE; AdamW lr .001, weight decay 1e-4, gradient cap 5, batch 256, at most 120 epochs, patience 20. Checkpoints minimize validation final loss then error, including initial epoch zero. This is inspired by attention-weighted labeled support sets in [Matching Networks](https://arxiv.org/abs/1606.04080) and permutation-invariant aggregation in [Deep Sets](https://arxiv.org/abs/1703.06114), not a reproduction of either complete model.

2. **Cross-fitted anchor transport.** Split training cases into five fixed shuffled folds (stratified for classification). For each fold, fit an ExtraTrees predictor `f_-fold` on the other four. For an anchor in that fold, predict `y_anchor + f_-fold(query) - f_-fold(anchor)`. Average with the original retrieval activations. Each anchor's correction model is trained without that anchor; validation/test labels are never used. Classification applies the formula to class-probability vectors and one-hot targets, then clips negative scores and normalizes. This is our combination of anchor differences with out-of-fold residual estimation, not an established named algorithm. Compare leaf sizes 1, 5, 20. All five forests contain 64 trees, depth 12, max_features .7; this costs five forests per candidate. No global cycle-consistency claim: anchors from different folds use different predictors.

3. **Error memory.** Store each training query's leave-one-out retrieval residual. Describe a retrieval situation by standardized representation, retrieved prediction and four statistics: nearest and activation-weighted mean Euclidean distance in the saved standardized representation, activation concentration, and target disagreement. Scale each descriptor coordinate with training mean/std. Retrieve similar training situations with Euclidean nearest neighbors and inverse-distance averaging; transfer their residuals to the current retrieved prediction. Compare 8/32 memories and correction multiplier .25/1. Regression transfers scalar residuals; classification transfers one-hot-minus-probability vectors, clips negatives and normalizes. Training residuals exclude the query's own case, but the frozen retrieval representation was originally fitted on all training labels; this is not a fully cross-fitted retrieval system. No new neural predictor.

4. **Direct ExtraTrees control.** Predict from the same frozen query representation without using retrieved labels. Use 64 trees, depth 12, max_features .7, leaf sizes 1/5/20. Including leaf size 1 avoids forcing the small direct training set to use only the smoothing levels designed for the much larger pair dataset. This is a direct-head control on learned representations, not a from-scratch raw-feature baseline or an equal-compute comparison.

5. **Retrieved-only pair trees control.** Repeat `ar1` pairwise ExtraTrees with only actual retrieved non-self training pairs, weighted to give each query equal total mass. Remove the eight random anchors. Keep both pair orientations, 64 trees, depth 12, max_features .7, leaf sizes 5/20. Inference matches `ar1`. The pair count changes, so this tests the practical training recipe rather than a perfectly matched sample-count ablation.

## Selection and recording

Cross-fitting applies to the new point-prediction heads only. The shared frozen representation and retrieval were fitted on the original full training set, so this is not cross-fitting of the entire NN-kNN pipeline.

There are **14 candidates per split**: 2 attention, 3 transport, 4 memory, 3 direct and 2 retrieved-only trees. Record 588 validation candidate units and 210 selected-family test units: **798 new units**, plus 42 reused `ar1` contexts. Within each family, select by validation error, then final validation NLL/MSE, then candidate ID. Evaluate only the winner of each family on test. All forest candidates use their final 64 trees, fitted/resumed in increments of 16; transport resumes within and between folds. Attention resumes optimizer, best checkpoint, shuffle and dropout RNG exactly. Completed units are reused before fitting or inference.

Report every result, including failures. Merge with all three `ar1` families, the `ar1` validation-choice policy and the established NN-CDH reference policies. Also report a predeclared validation choice across retrieval plus all seven adaptation families from `ar1`/`ar2`, excluding the direct predictor. Tie order: retrieval, previous pair trees, new retrieved-only pair trees, transport, error memory, attention, previous local ridge, previous pair neural. This is a dataset/seed selection policy, not a per-query gate. No test-driven clipping, weighting or exclusions.

Means retain equal dataset weights; report paired task/seed wins, classification fixes/harmful flips, regression direction/overshoot frequency and severity, and sensitivity to the two Zebra tasks. Separately compare direct trees with pairwise trees and quantify the immutable-neighborhood support limit for vote attention. Query labels are used for training/validation selection or descriptive test diagnostics only, never as inference inputs.
